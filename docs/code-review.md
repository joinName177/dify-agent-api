# Code Review 清单

本清单帮助作者自查和审查者收集证据。Git、PR、Review 和合并的强制规则以 `CONTRIBUTING.md` 为准。

## 作者自查

- PR 只解决一个可审查目标，描述目标、范围和非目标。
- 变更符合 `docs/go-backend-architecture.md`，没有跨层导入、反向依赖或重复实现。
- 行为变更具备能在旧实现失败的自动化测试，并覆盖错误、权限、取消、资源释放和边界路径。
- 外部输入在边界校验，错误和日志不泄漏 Secret、内部信息或完整 PII。
- OpenAPI、digest、生成物、配置 Schema、迁移和文档在同一变更中保持一致。
- 已执行适用的格式、静态分析、race、集成、契约、E2E、构建和安全检查，并附结果。

## 审查者检查

- 先核对目标和非目标，再确认 diff 只包含必要修改，没有顺带重构、死代码和无用依赖。
- 从不可信边界向内检查验证、权限、超时、取消、幂等、错误安全和资源释放。
- 从公开契约向内检查 Handler、Application、Domain、Infrastructure 和 Platform 依赖方向。
- 检查事务边界、SQL 参数化、并发行为、迁移锁影响和前向修复方案。
- 检查测试是否验证公开行为，缺陷回归测试是否能在旧实现失败。
- 涉及架构、身份、权限、数据、OpenAPI、迁移、供应链或发布时，确认对应 Owner 已审查。

## 审查结论

仅在适用 Required Checks 全部通过、讨论已解决、没有无主 TODO 或临时豁免、所需 Owner 批准有效时批准。发现阻断项时，说明受影响行为、风险和可验证的修正方向。
